# Repository Guidelines

## Project Structure & Module Organization
This is a Python/FastAPI multiplayer TTRPG application with Gemini narration and generated illustrations.
- `app/main.py`: FastAPI composition, middleware, static mounts, lifespan wiring, and domain-router registration.
- `app/api/routers/`: UI, auth, push, admin, session, character, turn, action, image, world-catalog, and chat/WebSocket route registration; keep public paths and response models stable.
- `app/services/`: extracted application behavior. `runtime.py` contains shared helpers and startup compatibility logic; focused services own sessions, characters, turns, proxy voting, chat, images, the read-only world catalog, push subscriptions, auth, admin, and UI responses. `ui_service.py` renders the pinned theme before frontend assets load.
- `app/worlds/models.py`, `registry.py`, `recipes.py`, and `packs/`: frozen Pydantic `WorldPack` contracts for classes, ability books, controlled mechanics, loot/crafting, item vocabulary, encounters/status presentations, maps, lore, narration and theme; validated ID/version/reference lookup and immutable declarative JSON definitions. Two existing full JSON packs and 13 strict `recipe_v1` JSON packs materialize to the same complete contract at import. Registered packs total 15; `dark_fantasy@1` remains the zero-argument legacy fallback only for rows lacking both persisted world fields.
- `app/models.py`, `database.py`, and `schemas.py`: SQLAlchemy persistence and Pydantic contracts, including pinned world-pack versions, stable class/ability IDs, five character attributes, named world-lore entries, death state, and the persistent per-campaign calendar-day image-generation quota.
- `app/dice.py`, `combat.py`, `inventory.py`, `loot.py`, and `magic.py`: weighted narrative intent/stat interpretation, server-side dice, pack-driven abilities and encounters, targeted ally support, death/stabilization/resurrection, equipment, loot/crafting, and legacy magic adapters.
- `app/map_generator.py`: deterministic campaign-map generation from a pinned map profile and map serialization.
- `app/gemini_service.py`: structured Gemini narration, campaign setup, and generated scene images.
- `app/push_service.py` and `generate_vapid_keys.py`: Web Push delivery and VAPID setup.
- `app/websocket_manager.py`: real-time event and chat broadcasting.
- `app/templates/index.html`: document shell with server-rendered `data-theme`, semantic colors, theme meta, and ordered frontend assets; `app/templates/partials/` owns the auth gate, lobby, character selection, game-table panels, and individual accessible modals.
- `app/static/js/app.js` composes the single Alpine `rpgGame` component from feature objects in `app/static/js/modules/`; named local Alpine components own story-hint and attribute-info disclosure state.
- `app/static/css/style.css` is the cascade entrypoint for token, base, component, inventory, map, lore, feedback, responsive, semantic theme, and `theme-art.css` world-presentation modules under `app/static/css/modules/`; `app/static/js/theme-bootstrap.js` applies a vetted local preview/last-known pack theme before CSS and updates theme metadata. `app/static/sw.js` must precache every versioned local frontend module.
- `tests/`: dice, combat, loot/crafting, API, lobby/admin, full turn resolution, WebSocket chat, current-world/frontend contracts, world-registry validation, synthetic stage-6 pack, stage-7 theme/selection, stage-8 NeoKatowice pilot, stage-9 world recipes/maps/books, and isolated Alembic migration coverage.
- `docs/WORLD_PACK_ROADMAP.md`, `docs/WORLD_DEPENDENCY_INVENTORY.md`, and `docs/adr/0001-versioned-world-packs.md`: staged multi-world roadmap, inventory of Dark Fantasy coupling, and the accepted direction for immutable declarative world packs.
- `alembic/` and `alembic.ini`: versioned schema migrations. Revision `0001_versioned_world_packs` creates a fresh schema or additively backfills existing campaigns; Docker upgrades to head before starting Uvicorn.
- `uploads/`: generated images; `data/`: Docker-mounted SQLite storage.

## Current Feature Baseline
The maintained feature set includes room-password/GM-PIN access, lobby/readiness, server-side random d20 rolls, narrative-first weighted intent/stat recognition with player correction, levels to 25, equipment claims and limits, targeted support, downed/stable/dead states and resurrection, phase-based encounters with status effects, location/enemy loot and post-encounter crafting, a persistent zoomable campaign map, shared categorized lore, proxy-action voting, chat/notes, accessible responsive PWA panels, Web Push, automatic session/WebSocket resynchronization, and one on-demand scene image per campaign per `Europe/Warsaw` calendar day. The validated registry exposes 15 `d20_v1` worlds through `GET /api/worlds`: unchanged `dark_fantasy@1` and `neokatowice_3077@1`, plus 13 stage-9 packs covering pirate, desert, Slavic, WWII-occult, witch, western, Viking, space-grimdark, dark-action, pastoral, cosmic-horror, consulting-detective, and humorous-dungeon campaigns. Dark Fantasy remains the legacy default. Campaigns pin exact pack ID/version; characters persist `class_id`, actions persist `ability_id`, and legacy name/`magic_*`/`active_boss_*` fields remain compatibility adapters. The generic runtime reads class starters/quick actions/ability books, controlled mechanics, action-stat cues, item vocabulary, loot/crafting search markers and item-name exclusions, enemy/status/map/lore profiles, scenario prompts, narration, image direction, and offline text from the pinned pack. Its frontend gets class, action and map-icon content from API. The GM world selector applies only to the *next* campaign on an explicit confirmed reset; direct changes to active campaign state stay rejected. The server renders controlled pack colors/shape on the document root and theme metadata; frontend may show a local, persistent `neon_preview` without changing the saved world, and SW caches versioned theme assets. `theme-art.css` adds distinct typography, restrained textures, thin trim, and mobile shadow/heading adjustments for all 15 world themes without changing published pack data; the humorous dungeon uses comic lettering and a halftone pattern. Display fonts use Google Fonts with system fallbacks. The app identity uses a mathematically exact, multi-genre D20 icosahedron SVG logo and precached raster PWA icon suite (192, 512, maskable, apple-touch, favicon), integrated directly into the auth gate. NeoKatowice 3077 is a fictional cyberpunk Poland pilot with Hacker, Neurotechnician, Exo Guard and Fixer books, starter gear, Katowice sectors, loot, encounters and art direction; its angular theme uses controlled `cut_corner` shape while Dark Fantasy stays rounded. Perception is the fifth canonical attribute across ORM/API/creation/cards/lobby/level-up/GM/items/dice/Gemini; sensory awareness must stay distinct from intellectual analysis. Peaceful stage-9 packs disable only automatic offline enemy naming through a validated narrative-profile flag; GM-triggered encounters still work. Stages 6–8 were manually accepted; stage 9 awaits owner acceptance. Keep this baseline synchronized with implementation changes.

Both GM campaign restart paths (`setup-scenario` and `reset-campaign`) clear `NamedLoreEntity` rows for the room and pending naming state in the same database transaction as the reset. Existing lore is retained during an active campaign and during additive migration; do not carry named discoveries into the next scenario or Gemini's turn context.

## Build, Test, and Development Commands
Use Python 3.11+ locally; Docker uses Python 3.12. Run commands from the repository root.
- `python -m venv .venv`: create a virtual environment; activate it in PowerShell with `.\.venv\Scripts\Activate.ps1`.
- `python -m pip install -r requirements.txt`: install application and testing dependencies.
- `Copy-Item .env.example .env`: initialize local configuration if `.env` does not exist.
- `python -m alembic upgrade head`: migrate the configured database after taking a backup of any active SQLite campaign.
- `python -m uvicorn app.main:app --reload --port 8000`: start the development server.
- `docker compose up -d --build`: build and start the container.

There is no separate frontend build step.

## Coding Style & Naming Conventions
Follow surrounding code: four-space Python indentation, `snake_case` functions and modules, `PascalCase` classes, and uppercase configuration constants. Preserve existing JavaScript naming and indentation. Use type annotations for backend interfaces and Pydantic models for structured payloads. Keep database access asynchronous. No formatter or linter is currently configured.

## Testing Guidelines
Tests use pytest, pytest-asyncio, and HTTPX ASGI clients. Name files `test_*.py` and functions `test_<behavior>`. Intent/stat tests cover ambiguous prose, including incidental shouts and defensive words used inside offensive declarations. No coverage threshold is configured. The suite command, for the maintainer's reference, is `python -m pytest tests/`. Integration tests can touch the configured database; use an isolated database when executing them.

Tests that deliberately reuse an existing turn must clear `resolved_at`, `mechanics_resolved_at`, and stale combat events before submitting a new action. Map assertions must resolve special nodes through `start_node_id` or `final_node_id`, because branch nodes are appended after the main path and list position is not a stable domain contract.

`tests/test_world_migration.py` creates an isolated legacy SQLite schema and invokes Alembic to verify additive backfills while preserving campaign progress. Migration tests must never point at `data/ttrpg_game.db` or another active campaign database.

WebSocket integration tests running against a persistent database must consume an optional initial `CHAT_HISTORY` snapshot before asserting the newly broadcast `CHAT_MESSAGE`; prior chat data is valid application state, not an event-order failure.

`tests/test_current_world_contract.py` is the compatibility gate for the staged multi-world refactor. Its route walker must continue to support FastAPI's lazily included routers. Update its fixture only for intentional public behavior changes. Backend/frontend moves must preserve the route table, WebSocket event names, current class starter sets, ability books, session shape, map profile, and UI markers recorded there. Consult `docs/WORLD_DEPENDENCY_INVENTORY.md` before moving world-specific behavior. Published world-pack versions described by ADR 0001 are immutable, declarative data and must not contain executable Python, JavaScript, arbitrary HTML/CSS, or untrusted external asset URLs.

World packs are loaded and fully validated when `app.worlds.registry` is imported. The 13 stage-9 `recipe_v1` JSON files are strict, frozen declarative shorthand expanded by `app/worlds/recipes.py` to a complete `WorldPack`; never bypass the final `WorldPack` validation or add world-ID-specific branches to the materializer. All collections in Pydantic models must remain tuples or frozen child models. Resolve explicit packs only by the complete `(id, version)` pair and fail closed for unknown values; the zero-argument lookup is the sole legacy fallback to `dark_fantasy@1`. New pack fields must use controlled schemas and mechanic keys rather than arbitrary mappings or executable behavior. Published pack IDs/versions and materialization rules are immutable; changing existing stage-9 recipe output requires a new version and migration plan.

Lore category IDs (`boss`, `location`, `npc`, `weapon`, `attack`) and all five attribute IDs are stable engine contracts; a pack changes their labels, not persistence IDs. `enemy_profile.lore_category_id` is `boss` until a versioned schema/API change. Only the published Dark Fantasy pack may use legacy `magic_*` compatibility fields as its primary display path; new pack logic uses `ability_book` and `ability_id`. Do not insert world-ID branches into routes, combat, or frontend content rendering. Stages 6–8 were accepted by the user; stage-9 per-world manual acceptance checklist is in `docs/WORLD_PACK_ROADMAP.md`.

Frontend refactors must preserve the property descriptors of the main Alpine component, rendered DOM selectors and accessibility attributes, CSS cascade order, and script initialization order. When adding or renaming a local JS/CSS module, bump its query-string version and the service-worker cache name, then include the exact versioned path in `PRECACHE_ASSETS`. There remains no separate frontend build step.

Theme profiles must declare all thirteen `#RRGGBB` semantic token IDs and use only vetted presentation IDs: typography `classic`/`modern`, texture `runes`/`grid`/`none`, icon set `classic`/`neutral`, shape `rounded`/`cut_corner`. Do not interpolate arbitrary pack CSS, font URLs, image URLs, or scripts into HTML. `ui_service.py` must keep theme bootstrapping server-side; `theme-bootstrap.js` runs synchronously before CSS and maintains the last validated pack theme for offline navigation. The local Neon preview is device-only and must clear on a pack switch. `GET /api/worlds` is a safe catalog; only the GM-confirmed `setup-scenario` reset may use `allow_new_campaign_reset` to change a pack while discarding the old campaign. Direct pack changes on active campaigns stay blocked. NeoKatowice room icons are declarative text glyphs exposed in `map_room_icons`; the default pack keeps the old map-icon fallback. Pack-driven `ui_copy` supplies short lobby/selection text using Alpine `x-text`, never arbitrary HTML. Narrative named weapons use a controlled target stat; the default remains `strength`, NeoKatowice chooses `agility`. Prologue noun/qualifier and offline party-presence copy are pack-driven with Dark Fantasy defaults identical to prior wording. Offline SVG decoration may branch only on controlled shape, not pack ID. `narrative_profile.offline_auto_enemy_naming` defaults to true for old packs and is false for peaceful stage-9 recipes; do not replace it with world-ID checks.

Keep world-specific visual choices in the app-owned `theme-art.css` keyed by validated `data-theme`; do not copy CSS or external font URLs into packs. NeoKatowice's theme ID is `neo_katowice`, distinct from its world-pack ID `neokatowice_3077`; CSS selectors must use the former. Dark Fantasy cards have small CSS metal corner caps and rivets; NeoKatowice use thin cyan outlines and restrained text glow inspired by the owner's supplied mobile reference. Generic `ui-world-emblem` and `ui-theme-icon` classes hide castle/sword glyphs for neutral icon sets while the lobby uses world-neutral wording. Preserve narrow borders, readable narration, and small-screen layouts when refining those profiles. The GM panel can temporarily preview the selected catalog world's theme on the current device before reset; it does not alter the pinned campaign, survives same-world session refreshes, and clears on a pack switch, closing the GM tools, or explicit restore. Update versioned CSS/JS URLs and service-worker precache together. Consult the visual direction and per-world acceptance rows in `docs/WORLD_PACK_ROADMAP.md`.

Perception is the fifth canonical attribute. Historical characters backfill to `0`; their four prior attributes and HP/XP/level, the character-creation point budget, and the HP formula remain unchanged. Perception/awareness/sensory actions must stay distinct from intellect/knowledge/analysis actions. Every roadmap stage includes a user-facing local build-and-click acceptance checklist, with a separate UI acceptance row for each stage-9 world. Keep those checklists current when an implementation changes the expected manual verification path, and always direct manual state-changing checks to an isolated database or a copy rather than the active campaign database.

## Commit & Pull Request Guidelines
History uses short English subjects such as `Images fix` and `app as a PWA`; no strict prefix convention is established. Write descriptive subjects focused on the change. PRs should explain behavior changes, reference relevant issues, and include screenshots for UI changes. Report only validation actually performed. At the end of every completed change, propose a short English commit subject to the user; do not create the commit unless explicitly requested.

## Security & Configuration
Keep secrets in `.env`; update `.env.example` when adding settings. Never commit credentials, SQLite databases, or generated uploads.

## Agent Instructions
Respond in Polish, concisely, as to an engineer. State concrete changes and relevant limitations without unnecessary explanation. Do not run tests or propose running them; the user runs tests independently unless explicitly requesting otherwise.

Treat documentation as part of every completed change. Before finishing any implementation, configuration, structure, command, or workflow change:
- update `README.md` so its feature list, setup instructions, configuration, project tree, and test inventory match the repository;
- update `AGENTS.md` with the corresponding repository guidance or current feature baseline;
- mention both documentation updates in the final summary;
- finish the final response with `Proponowana nazwa commitu: <short English subject>`.

Do not leave either Markdown file stale merely because a change is small. If a change does not affect an existing section, add a concise note to the most relevant section instead of creating an unrelated changelog entry.
